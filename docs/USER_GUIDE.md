# YOLO 工作台使用指南

本工具面向 Windows 10 22H2 / Windows 11 x64 的本地矩形目标检测工作流：整理图片、标注、训练、评估、部署验证和导出。以下按钮名称对应当前桌面程序。

## 1. 离线首次启动

1. 将**完整便携目录**放在有写入权限、空间充足的位置。工程交付位置为 `output/YOLOWorkbench/YOLOWorkbench.exe`；移到其他电脑时，复制整个 `YOLOWorkbench` 文件夹。
2. 保留 EXE 同级的 `_internal/`、`runtime/`、`app/`、`fonts/`、`models/`、`scripts/`、`docs/`。包内还包含 `source/` 源码、`licenses/` 许可和 `build-manifest.json` 构建记录。训练和推理分别使用 `runtime/train/python.exe`、`runtime/inference/python.exe`，不要仅复制 EXE。
3. 双击 `YOLOWorkbench.exe`。进入“设置”，检查“训练 Python”“推理 Python”“模型缓存”和“默认项目目录”。使用随包环境时保留默认路径，然后点“运行环境诊断”。
4. 查看诊断和“日志”中的错误。先以 `cpu` 完成首次工作流；CPU 基础包不代表已经配置好 CUDA 或 TensorRT。
5. 检查 `models/` 中的 `yolov8n.pt`、`yolo11n.pt`、`yolo26n.pt`。这三种 n 规格权重是当前预准备缓存；选择其他规格时需要对应的本地权重。
6. 回到“标注训练”，新建或打开项目。依赖、字体和所需权重齐全后，标注、训练、评估和导出均可离线运行。运行任务时不会自动安装依赖或补下载权重。

不需要在目标电脑额外安装开发工具。若运行环境文件缺失，应补齐完整便携包；“准备所选训练模型（需联网）”只准备模型权重，不能修复缺少的 Python 运行环境。

四个主入口的用途：

| 入口 | 用途 |
|---|---|
| 标注训练 | 项目、图片、类别、采集、数据检查与划分、训练参数 |
| 验证 | 现场识别、数据集评估、模型导出、性能测试 |
| 日志 | 按任务、级别和文字筛选，复制或导出日志 |
| 设置 | 独立运行环境、模型缓存、项目目录、截图快捷键和诊断 |

“训练监控”可展开底部任务面板。双击任务查看详细记录；选择任务后使用“打开产物”定位输出目录。

## 2. 新建项目并导入数据

1. 点“新建项目”，选择父目录，填写项目名称和每行一个的初始类别。项目目录必须为空。`input/` 为原始资料目录，不能作为工作项目。
2. 点“导入数据 ▾”，选择适合的入口：
   - “图片文件”：导入选中的原图，进入待标注列表。
   - “图片 / YOLO 目录”：导入图片及可匹配的 YOLO 标签、类别和旧配置。
   - “YOLO 数据集 ZIP”：导入压缩包中的标准目录结构。
3. 只有确定来源的**空标签已经人工审核**时，才勾选导入窗口中的空标签确认选项。
4. 等待导入结果，核对新增、重复、失败和警告。失败的文件不会假装成功；修复来源后可再次导入，内容重复的图片会跳过并保留当前标注。

常见 YOLO 结构为 `images/train/a.jpg` 对应 `labels/train/a.txt`，或图片和同名 TXT 放在同一目录。类别可来自 `labels.txt`、`.names` 或数据集 YAML 的 `names`；名称顺序必须一致。已有项目按类别名称匹配，遇到新类别时先在“管理类别”中新增，或使用空项目导入。

来源文件保持原样，工作台使用项目内的独立图片副本。ZIP 的绝对路径、越界路径、链接、重复路径及异常压缩包会被拒绝；不会执行 YAML 中的下载命令。较大的导入可以点击状态栏“取消当前数据操作”：已完整入库的图片保留，重新导入会去重。

三种审核状态必须区分：

| 显示状态 | 含义 |
|---|---|
| 未标注 | 尚未完成审核；包括缺失标签和未经确认的空标签 |
| 已标注 | 存在有效目标框 |
| 已确认无目标 | 用户明确确认该图没有目标，可作为负样本 |

导入带有效 train/val 清单的数据集时，空项目可保留来源划分。导入报告会说明来源划分无法保存的原因。

### 导入旧训练与模型配置

通过“图片 / YOLO 目录”选择含 `训练参数.json`、`模型配置.json` 的目录，即使目录只有配置和类别文件，也可以导入配置。配置通过类型和取值校验后保存；缺省字段保留项目已有值。

例如旧配置中的输入尺寸 320、3000 epochs、batch=-1、device="0"、workers=12 会被保留。导入后检查右侧训练参数与“验证”页的系列、输入尺寸、后端和置信度。模型文件路径仍需在“模型”或“初始权重”中选择实际存在的文件。

如果当前电脑没有可用 CUDA，主动将训练设备切换为 `cpu`，再确认 Batch 与 Workers；不要直接用旧机器的 GPU 配置开始训练。新项目默认 YOLOv8n、640、100 epochs；CPU 默认 Batch=4、Workers=0。演示项目和导入项目可以有自己的已保存参数。

## 3. 标注、审核与类别管理

1. 在左侧选择图片。使用搜索和状态筛选缩小范围。
2. 在右侧选择类别，点“绘框 W”，从目标左上角拖到右下角创建矩形。
3. 切到“选择 V”，拖动框移动位置，拖动角点或边缘控制点调整尺寸。选中框后选择其他类别可改类。
4. 修改后稍等，右上方状态应变为“已保存”；也可点“保存 Ctrl+S”。切图前会尝试保存，失败时应先处理提示，不要把“等待保存”当成已落盘。
5. 没有目标的图片点“确认无目标”。若图中已有框，会先提示清空确认；可通过撤销恢复。
6. 使用“下一未标注”继续审核。多选图片后点“回收 / 恢复”进行逻辑回收；在“回收区”选择图片后可恢复。

先点击画布，再使用标注快捷键。搜索框、类别编辑框和训练参数框有焦点时，按键用于该输入框；需要继续绘框时重新点击画布。回收区图片只读，后台数据操作期间标注暂时不可用。

| 画布快捷键 | 操作 |
|---|---|
| W / V | 绘框 / 选择 |
| 滚轮 / 按住空格拖动 | 缩放 / 平移 |
| F | 适应画布 |
| 1–9 | 选择前九个类别；有选中框时切换其类别 |
| Ctrl+C / Delete | 复制选中框 / 删除选中框 |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做 |
| Ctrl+S | 保存当前标注 |
| A、左方向键 / D、右方向键 | 上一张 / 下一张 |
| N / Esc | 下一未标注 / 取消选中 |

“管理类别”支持添加、双击重命名、上移、下移和移除。先查看迁移预览，确认受影响图片和将删除的框，再应用。删除最后一个目标框不会自动确认该图无目标。

“恢复迁移”选择项目 `history/` 中的类别迁移记录。迁移后已有新导入、标注编辑或其他事实变化时，工具会拒绝覆盖，需要重新制定类别映射。历史模型和训练快照保留训练时的类别顺序。

## 4. 从桌面或窗口采集

1. 在“标注训练”顶部选择“截图来源”。点“刷新窗口”更新列表，或点“指向选窗”，在三秒内将鼠标移到目标窗口。
2. 先点“预览”检查当前画面和客户区；预览画面会显示在“验证”页。
3. 点“单张截图”保存一张并回流到当前项目。默认全局快捷键为 **Ctrl+E**，可在“设置”中修改；快捷键被其他程序占用时查看日志，仍可使用按钮截图。
4. 设置间隔，点“开始定时截图”；默认间隔为 5 秒。再次点击“停止定时截图”结束。
5. 新截图进入“未标注”。采集会话和来源会随样本保留，之后仍需人工标注或确认无目标。

保持目标窗口可见且客户区有效。最小化、隐藏、关闭或持续没有新帧时，查看状态和日志，恢复窗口后重新开始；首版不保证最小化窗口持续采集。不同 DPI、多个显示器和受保护窗口应在实际使用环境中先做预览检查。

标注快捷键与全局截图快捷键用途不同：Ctrl+E 会请求截图。进入数据导入、检查等操作期间，以界面的任务状态为准，避免重复触发多个采集任务。

## 5. 检查和划分数据

1. 点“数据检查”，查看损坏图片、缺失或非法标签、重复框、异常尺寸、小目标、类别分布及数据泄漏提示。
2. 处理错误，再点“数据划分”。默认训练比例 0.8、测试比例 0、seed=42，并按采集会话分组；剩余比例属于验证集。
3. 未标注图片应先完成审核；确实要暂时排除时，显式勾选“明确排除未标注图片”。
4. 需要独立测试集时设置非零测试比例，确认 train、val、test 都有足够的独立样本。

按会话分组时，同一会话不会分到不同集合。训练/验证至少需要两个独立组，增加测试集至少需要三个。分组比例按组数分配，实际图片比例可能不同。按不同场景、时段分别采集并保留会话，有助于检查同源数据泄漏。

**新增、回收、重新审核图片，或调整类别后，应重新检查并按需要重新划分。** 启动训练会复用已保存的划分，不会自动把后来新增的图片塞进旧清单。失效的划分需要先修复，跨集合重复图片或会话泄漏会阻止生成训练快照。

## 6. 选择权重并训练

### 权重缓存与随机初始化

默认的“初始权重”为空时，程序查找模型缓存中对应的权重，例如 YOLOv8 + n 对应 `yolov8n.pt`。随包预准备了 v8、11、26 的 n 规格；s、m、l、x 需要另外准备，不能只切换规格就假定文件已经存在。

离线时有两种选择：选择已存在的本地 PT 权重；或者勾选“从模型结构开始训练（随机初始化）”。随机初始化不需要预训练 PT，但实际效果仍依赖数据量和训练过程。

联网准备时，先在“标注训练”选择系列和规格，再在“设置”点“准备所选训练模型（需联网）”。该按钮准备当前选中的模型；也可以在**便携包根目录**打开 PowerShell，例如：

```powershell
& .\runtime\train\python.exe .\scripts\prepare_models.py --destination .\models --models yolov8s.pt
```

准备完成后再离线使用。若设置了自定义模型缓存，应将 `--destination` 改成该目录，或通过“初始权重”直接选择文件。

### 启动与监控

1. 选择模型系列 v8/11/26 和规格 n/s/m/l/x，确认初始权重或随机初始化方式。
2. 在“基础”设置尺寸、Epochs、Batch、设备、Workers 和早停。CPU 使用正数 Batch；CUDA 可用 -1 自动 Batch，但必须有匹配的独立运行环境和硬件。
3. “高级”中的优化器、学习率、权重衰减、AMP、缓存和 Mosaic 会参与最终配置。“专家”使用 YAML，可覆盖允许的高级参数；数据路径和输出目录由工具管理。
4. 点“检查并开始训练”，核对“生效参数”、是否排除未标注以及所用模型，确认“冻结数据并训练”。
5. 工具先检查数据并创建快照，再启动独立训练任务。在底部“训练监控”观察进度、损失、指标和资源；“日志”中可筛选该任务。

每次训练使用冻结的图片、标签、类别、划分和参数。训练开始后继续标注，影响的是后续任务。任务运行期间保持当前项目打开；结束后再切换项目。

### 停止、恢复和继续训练

先在任务面板选中对应记录：

| 操作 | 用途与结果 |
|---|---|
| 停止并保存 | 请求在安全保存点结束；当前轮可能仍需完成保存和验证，请等待状态变化 |
| 强制结束 | 结束本工具拥有的任务进程；当前 Epoch 未保存的进度可能丢失，保留已有完整检查点 |
| 断点恢复 | 使用该记录的 `resume.pt`、原始快照和完整训练状态继续原计划；优化器等状态一并恢复 |
| 权重续训 | 选择该记录的 best.pt，若没有则使用 last.pt；回到参数面板，检查后启动新任务，可使用新数据和新轮数 |

已完成的训练计划不能再用“断点恢复”增加轮数。找不到完整 `resume.pt`、需要换数据/类别/训练计划，或只有普通 best.pt/last.pt 时，使用“权重续训”。恢复和续训都会产生新的任务记录，不覆盖旧结果。

## 7. 评估、现场识别与问题样本

### 标准数据集评估

1. 在“验证”顶部选择可由 Ultralytics 加载的模型，通常选择训练得到的 `best.pt`。
2. 在“数据集评估”选 `val`；若已划分非空测试集，可选 `test`。
3. 点“评估当前项目数据集”。程序冻结当前有效划分，并计算 Precision、Recall、mAP50、mAP50–95。
4. 查看指标和任务产物。当前项目的类别名称及顺序必须与模型训练时一致；类别变更后应使用匹配的模型和数据。

这里的标准评估指标来自 Ultralytics。现场识别的框数、置信度和耗时用于检查部署行为，不能代替有真值标签的数据集评估。

### 现场识别

1. 选择 PT、ONNX、NCNN param，或导出包的清单；NCNN 的 param/bin、类别文件应保持配套。
2. 选择模型系列和验证后端：CQ_AI、NCNN、通用 PT 或通用 ONNX。核对类别文件、实际输入尺寸、设备和置信度，默认置信度为 0.5。
3. 选择图片、图片目录、视频、窗口或桌面；窗口输入先“刷新窗口”，选择目标并核对“仅客户区”。
4. 点击“单次识别”或“连续识别”，查看画面、类别、置信度和原图坐标。目录和视频按来源内容处理；显示帧率上限不代表能够达到该 FPS。
5. 点击“停止识别”结束。发现误检或漏检时，点“保存问题样本 → 待标注”，填写问题说明，再回“标注训练”人工审核。

CQ_AI 的 IoU 固定为 0.45。其他后端是否允许调整 IoU，以加载后显示的能力为准；端到端模型可能没有 NMS，YOLO26 的不同导出格式也可能不同。模型冻结的类别映射用于解释输出，不会从当前项目猜测类别。

### 性能测试

在“现场识别”先选固定图片和模型，再到“性能测试”设置预热与采样次数，点“开始性能测试”。默认预热 20 次、采样 200 次。比较结果时保持模型、尺寸、后端、精度和设备一致，同时查看 P50/P95、吞吐量和端到端耗时。

一次短测试不能证明 30 分钟稳定性；当前电脑的结果也不代表另一台机器、手机或不同后台负载下的性能。

## 8. 导出模型包

1. 在“验证”顶部选择本地 PT 权重及正确的模型系列。
2. 打开“模型导出”，选择使用端、格式和固定输入尺寸。
3. 点“导出并验证模型包”，等待任务完成。每次创建新的目录；只有结构检查及独立进程加载、执行通过，才报告成功。
4. 用“打开产物”或导出结果中的路径找到模型包，连同清单、标签和使用示例一起保存。

| 使用端 | 选择范围 |
|---|---|
| 通用模型 | PT / ONNX / NCNN；YOLO26 使用通用路径 |
| CQ_AI / OpenCV | YOLOv8 / YOLO11，ONNX，固定 320 或 640，FP32、Batch=1、opset12 |
| AScript v8 | 仅 YOLOv8，NCNN，固定 640；保留 param/bin、labels.txt 和随包入口示例 |

包内 `manifest.json` 保存实际模型结构、类别和文件哈希，`README.txt` 和示例说明加载方式。带 `failure.json` 的失败目录用于定位问题，不能当作已验证模型包发布。桌面 CPU 的加载验证不代表 Android/AScript 真机、CUDA 或 TensorRT 验收；使用端仍需用真实样本验证。

## 9. 合成演示：先走通操作流程

随包的 `scripts/create_demo_project.py` 可离线生成形状演示项目。在**便携包根目录**打开 PowerShell：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'app'
& .\runtime\train\python.exe .\scripts\create_demo_project.py .\projects\shape-demo
& .\YOLOWorkbench.exe --project .\projects\shape-demo
```

脚本默认创建 36 张 640×384 合成图，类别为“红色方块”和“蓝色圆形”，包含已确认负样本，并保存默认划分。演示训练参数为 YOLOv8n、320、10 epochs、CPU、Batch=4、Workers=0。已有非空同名目录会被拒绝，请换一个新项目名称。

可以先检查标签、训练，再查看评估和导出。**合成图上的成功运行或高指标只说明这个演示流程的结果，不能证明真实业务准确率、目标设备兼容性或生产稳定性。** 正式使用时建立独立业务数据集，并保留未参与训练的验证/测试样本。

## 10. 文件位置、恢复与常见问题

| 位置 | 保存内容 |
|---|---|
| 便携包 `runtime/`、`app/`、`fonts/` | 独立 Python 运行环境、任务程序和离线字体 |
| 便携包 `source/`、`docs/`、`scripts/` | 应用与测试源码、文档、准备及演示脚本 |
| 便携包 `models/` | 预准备权重及缓存清单，可在设置中改位置 |
| 便携包 `userdata/` | 设置、桌面日志和未打开项目时的任务数据 |
| 便携包 `projects/` | 默认项目位置；新建时也可选择其他目录 |
| 项目 `project.json`、`labels.txt` | 项目信息、类别、已保存参数 |
| 项目 `assets/`、`labels/`、`records/` | 托管图片、工作标签、审核及来源事实 |
| 项目 `splits/`、`snapshots/` | 保存的划分、每次训练/评估的冻结数据 |
| 项目 `jobs/` | 各任务请求、事件、stderr.log、训练权重、指标和其他产物 |
| 项目 `exports/` | 打开项目时生成的模型导出包 |
| 项目 `history/`、`feedback/` | 类别迁移记录、问题样本及说明 |
| 项目 `index.sqlite3` | 可从事实文件重建的检索索引 |

关闭项目和任务后，可整体移动项目目录；托管资产使用相对路径，原始导入目录不再是读取依赖。移动便携包后，如曾手动填写过绝对运行环境、缓存或项目路径，需要到“设置”检查；旧的“最近项目”路径失效时重新选择实际目录。

异常退出后重新打开项目，工具会尝试恢复中断的保存、导入并重建索引。若提示项目正由另一实例打开，先关闭该实例；不要通过删除锁文件绕过正在工作的实例。恢复失败时保留项目文件和日志，避免手工修改 `records/` 或覆盖图片来尝试修复。

| 提示或现象 | 处理步骤 |
|---|---|
| 权重尚未准备 | 检查当前系列/规格和缓存目录；选已有本地 PT，或选择随机初始化；需要下载时显式联网准备 |
| 未标注图片阻止训练 | 完成人工审核，或明确选择排除；若旧划分失效，先重新划分 |
| 采集会话跨集合 / 独立组不足 | 检查来源和会话，补充独立采集数据，并重新分组划分 |
| 模型类别映射不同 | 核对模型训练类别、当前项目类别及顺序，选择匹配的数据与模型 |
| 不能断点恢复 | 查找该任务完整 resume.pt；原计划已结束或缺少完整状态时使用权重续训 |
| 窗口无画面 / 无新帧 | 恢复目标窗口可见状态，重新刷新和预览；查看源状态与日志 |
| CUDA / TensorRT 不可用 | 先使用已验证的 CPU 路径；检查额外环境与实际 NVIDIA 设备，不把 CPU 成功视为 GPU 成功 |
| 保存失败或任务失败 | 保留当前项目，查看“日志”和对应任务 stderr.log，确认磁盘空间、权限和运行环境后重试 |

遇到错误时，记录项目路径、任务 ID、操作步骤，并使用“日志”的导出功能保存信息。更细的数据接口与恢复规则见 [DATA_WORKFLOWS.md](DATA_WORKFLOWS.md)，推理和采集能力说明见 [INFERENCE_CAPTURE.md](INFERENCE_CAPTURE.md)。

若尚未进入界面就退出，查看 `userdata/startup-error.log`；交付目录不可写时，备用位置为 Windows 临时目录下的 `YOLOWorkbench-startup-error.log`。请保留完整便携目录，不要用其他 Python、Qt 或 OpenCV 安装中的同名 DLL 覆盖包内文件。
