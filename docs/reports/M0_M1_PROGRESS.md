## 实际兼容测试

| 项目 | 结果 | 证据范围 |
|---|---|---|
| CQ_AI CPU | 通过 | 用户 ONNX，[1,3,320,320] → [1,10,2100]；阈值 0 的 1931 个检测结果，适配层与直接引擎逐项相同 |
| AScript 样板 NCNN CPU | 通过结构检查 | 固定 640，out0 [10,8400]；零输入，不等于 Android 实际识别 |
| 普通 NCNN 样板 | 可执行，契约不兼容 | 三路 [40,40,70] / [20,20,70] / [10,10,70]，不能作为 AScript 已解码单输出包 |
| YOLOv8n | 通过 | 随机初始化架构前向、opset12 ONNX 导出、ORT CPU 执行 |
| YOLO11n | 通过 | 同上 |
| YOLO26n | 通过通用路径 | 输出 [1,300,6]，不交给 CQ_AI v8/11 解码器 |
| CPU 实际训练 | 通过 | 合成六图、64 输入、1 epoch、验证；另存 resume.pt 包含 optimizer 与 epoch |

机器结果汇总由脚本生成在 `compatibility-baseline.json`。首轮 NCNN 探针因临时输入数组生命周期失败；修复后目标样板与普通样板均通过。CQ 对照探针最初同时持有两个 Engine，后者关闭释放进程资源；改为顺序生命周期后通过。见 [生命周期决策](../ADR/ADR-0001-runtime-and-model-lifetimes.md)。
